# Grillme: Hermes host install, last 30 days, 50 questions

Generated 2026-08-29 with the official `grill-me` skill shape (frontier
rounds: question + recommended answer). There is no local grillme skill in
this repo; the MIT copy lives at
`optional-skills/software-development/grill-me` in
[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)
(HEAD `4209d37`, package `0.20.6`, same-day merges including `#97872`
keeping the skill name). Facts are from that clone, `website/docs`,
`hermes_cli/web_server.py`, and a live `hermes serve` on this VM.

This is not a user interview. Each answer was looked up or executed here.

## Recommendations

- Keep `--serve` until Hermes ships an unauthenticated companion claim.
- Pin `hermes plugins install` with a 40-char SHA when a public repo exists.
- Never put a generated `mk_` token on `/api/ws`.
- Do not clone the kanban SPA, desktop TUI, or plugin store.
- Site tokens stay chrome-only. Dashboard radius stays `0.5rem`.

---

### Q1. Does Hermes ship a first-party phone app we should wait for?

**A:** No. Last-30-days main (`4209d37`) still has dashboard, desktop, Termux,
and messaging gateways. No companion iOS/Android QR product.

**Suggestion:** Ship Manage.kar as the phone. Do not wait.

### Q2. How many pairings does official Hermes actually have?

**A:** Three, orthogonal: WhatsApp Web QR, DM pairing
(`hermes pairing approve <platform> CODE`), dashboard session + `/api/ws`.

**Suggestion:** Map our QR onto dashboard attach only. Never call DM pairing
a machine pair.

### Q3. Is the WhatsApp QR the transport we want?

**A:** No. `plugins/platforms/whatsapp` (`kind: platform`) starts a Node
Baileys/web.js **bridge**. The QR logs into WhatsApp Web, not `/api/ws`.

**Suggestion:** Copy the ceremony (host shows QR). Keep our transport as
`GET /api/status` → `/api/ws?token=` → `session.create`.

### Q4. Can we install a plugin from any MIT GitHub repo?

**A:** Yes. `hermes plugins install owner/repo --enable`. Production should
add `--ref <40-char-sha>`. Tags and short SHAs are refused.

**Suggestion:** Keep `packages/hermes-managekar-plugin/` extractable. `gh`
here cannot create the public repo.

### Q5. Is there a one-click install link?

**A:** Yes. `hermes://plugin/install?repo=owner/repo` (`&enable=1`, `&force=1`).
Legacy `hermes://plugin-agent/…` routes to the same dialog.

**Suggestion:** Document the link. Do not build an in-app plugin store.

### Q6. Are user platform plugins on by default?

**A:** No. Third-party code in `~/.hermes/plugins/` is opt-in via
`plugins.enabled`. Bundled platforms load automatically.

**Suggestion:** README must say `hermes plugins enable managekar` or
`--enable`. A `cp` without enable will not mount `/api/plugins/managekar/`.

### Q7. Where does a dashboard tab come from?

**A:** `~/.hermes/plugins/<name>/dashboard/manifest.json` with `"api":
"plugin_api.py"` exporting `router = APIRouter()`. Mount prefix:
`/api/plugins/<name>/`.

**Suggestion:** Keep the plugin name `managekar`.

### Q8. Are plugin API routes public on localhost?

**A:** No. `PUBLIC_API_PATHS` is `/api/health`, `/api/status`, a few read-only
config/theme feeds, and `/api/cron/fire`. `/api/plugins/*` is not listed.
This VM: pair without header → **401**.

**Suggestion:** The old “localhost plugins are open” line was wrong. Delete it.

### Q9. Does `--insecure` open those routes?

**A:** No. `hermes_cli/subcommands/dashboard.py` marks `--insecure` DEPRECATED
/ NO-OP. A public bind always needs password or OAuth.

**Suggestion:** Bind `127.0.0.1` and tunnel. Never advertise `--insecure`.

### Q10. What is public without a token?

**A:** `GET /api/status` and `GET /api/health`. Proven: version `0.20.6`,
`auth_required: false` on loopback, `gateway_running: false`.

**Suggestion:** Status is a liveness probe, not a pair.

### Q11. How does `/api/ws` authenticate on loopback?

**A:** `?token=` must equal `HERMES_DASHBOARD_SESSION_TOKEN` (or the ephemeral
token injected into the SPA). Gated mode uses single-use tickets instead.

**Suggestion:** Claim must return that session token, not `mk_…`.

### Q12. What happens if claim returns `mk_`?

**A:** Official `/api/ws?token=mk_…` on this VM returned **403 Forbidden**.
`session.create` never ran.

**Suggestion:** Require `--token` / `MANAGEKAR_DASHBOARD_TOKEN` in host docs.

### Q13. Can the dashboard tab mint a usable token without env?

**A:** After this change, mint copies `X-Hermes-Session-Token` when
`MANAGEKAR_DASHBOARD_TOKEN` is unset. Phone claim on `:9119` still 401s.

**Suggestion:** Still run `--serve` for the phone. The header copy only helps
the tab’s later claim-from-same-browser story, not a handset.

### Q14. Why `--serve` at all?

**A:** Phones cannot send `X-Hermes-Session-Token`. D012: `:9120` mints/claims
without it and returns `{ endpoint: :9119, token }`.

**Suggestion:** Keep `--serve` as the phone path until Hermes adds a public
companion claim route.

### Q15. Does `hermes serve` show `/pair/<id>`?

**A:** No. Headless backend: this VM got 404
“web UI disabled — use `hermes dashboard`”.

**Suggestion:** Put the scannable QR on `--serve` `/pair/<id>` (SVG) and in
the dashboard tab (`qr_svg`).

### Q16. `hermes dashboard` vs `hermes serve`?

**A:** Same `start_server`. `dashboard` opens the SPA. `serve` sets
`headless_backend=True` and skips the UI build. Desktop/remote clients use
`serve`.

**Suggestion:** Host install docs should start with `hermes serve` plus
`--serve` on 9120.

### Q17. What extra installs the dashboard?

**A:** `[web]` (`fastapi`, `uvicorn`, `starlette`, `python-multipart`).
Comments still say “hermes dashboard” but the extra name is `web`.

**Suggestion:** `uv pip install -e ".[web]"`. Do not tell people `[dashboard]`.

### Q18. Did this VM get Hermes running without API keys?

**A:** Yes. `uv` + `[web]`. `session.create` returned `session_id` with
`info.model: dummy`, `lazy: true`. No OPENAI/GROQ/OPENROUTER env.

**Suggestion:** Do not block pairing on “set a key first”. Keys are for chat
turns, not the socket handshake.

### Q19. Is `gateway_running: false` a failed pair?

**A:** No. That flag is the messaging gateway (WhatsApp/Telegram/…). Dashboard
JSON-RPC is a different process surface.

**Suggestion:** Presence for a paired machine is `/api/status` + WS, not
`gateway_platforms`.

### Q20. What must `--pair-base` be for a real phone?

**A:** A URL the phone can open: LAN, Tailscale, or a tunnel.
`127.0.0.1` is only for same-host tests.

**Suggestion:** Cloudflare in front of the PWA does not pair the phone to
this VM’s loopback Hermes.

### Q21. What is in the QR?

**A:** Compact `managekar.pair.v1|<pairId>|<claimUrl>`. Full JSON is too long
for versions 1–5 L.

**Suggestion:** Encode compact. Keep JSON for paste. Draw SVG + ASCII.

### Q22. Who displays the QR?

**A:** The host: terminal ASCII, `:9120/pair/<id>` SVG, Hermes Manage.kar tab
`qr_svg`. The phone scans or pastes.

**Suggestion:** Keep the in-app MK- pattern labeled **Not a real QR yet**.

### Q23. Can the phone mint?

**A:** It should not. Mint is a privileged host action.

**Suggestion:** Phone only claims + attaches.

### Q24. What is the claim contract?

**A:** One `POST` → `{ endpoint, token }`. Second claim 409. Expired 410.
Unknown 404. Proven on both official plugin (with header) and `--serve`.

**Suggestion:** Do not retry claim on a 409. Attach with the first token.

### Q25. Does official claim on `:9119` work for a phone?

**A:** Only if the phone already has the dashboard session header. This VM:
claim without header → 401.

**Suggestion:** Point `claimUrl` at `--serve` via `MANAGEKAR_PAIR_BASE`.

### Q26. How do we install Hermes on a VPS the same way?

**A:** Clone MIT repo, `uv venv`, `uv pip install -e ".[web]"`,
`HERMES_HOME=…`, `plugins.enabled: [managekar]`,
`HERMES_DASHBOARD_SESSION_TOKEN=…`, `hermes serve --host 127.0.0.1 --port 9119`,
`python cli.py --serve --token … --pair-base https://pair.example`.

**Suggestion:** Same script for laptop and VPS. Only `--pair-base` changes.

### Q27. Can we `hermes plugins install` this folder today?

**A:** Not as `owner/repo` until it is a public Git repo. Local path:
`cp -R packages/hermes-managekar-plugin ~/.hermes/plugins/managekar`.

**Suggestion:** Do not pretend a public plugin repo exists.

**Suggestion:** One ticket type. Many machines. Presence per machine.

### Q41. Does a sleeping laptop stay connected?

**A:** Not by this QR. Relay is a later Hermes experimental contract (D

**Suggestion:** Be honest: “reachable / asleep / unreachable”.

### Q42. Cloudflare preview of Manage.kar — does it pair?

**A:** The PWA can load. Claim to `127.0.0.1:9119` from a real phone will not

**Suggestion:** Publish `--pair-base` as the tunnel to **9120**, not the PWA.

### Q44. Plugin kind?

**A:** `kind: platform` so `hermes plugins install` matches WhatsApp/IRC.
Chat after claim is still `/api/ws`, not `adapter.send`.

**Suggestion:** Keep `send()` as a no-op success. Do not grow a second inbox.

### Q45. Index vs sideload?

**A:** Official index is
`https://raw.githubusercontent.com/NousResearch/hermes-plugin-index/main/index.json`.

**Suggestion:** Sideload until a public MIT repo exists. Do not fake a listing.

### Q46. Project plugins vs user plugins?

**A:** `./.hermes/plugins` Python `api` files are **not** auto-imported
(GHSA-5qr3-c538-wm9j). User plugins under `~/.hermes/plugins/` are, if
enabled.

**Suggestion:** Always install into `~/.hermes/plugins/managekar`.

### Q47. Session token lifetime?

**A:** Ephemeral per `hermes serve` process unless
`HERMES_DASHBOARD_SESSION_TOKEN` is set. It dies when the process exits.

**Suggestion:** Set the env on systemd/docker so phones survive a restart
only if you persist that token (and rotate it).

### Q48. Host header / DNS rebinding?

**A:** Dashboard validates Host on loopback. Random public hostnames to
`127.0.0.1` are rejected.

**Suggestion:** Tunnel with a hostname you configure, or stay on loopback
+ `--serve` on an advertised pair-base.

**Suggestion:** Re-read `PUBLIC_API_PATHS` if they ever add a companion

`hermes plugins enable managekar`, export the session token, run
`hermes serve` + `hermes managekar --serve --pair-base <reachable-url>`.
Scan the SVG/ASCII QR from Manage.kar. Publish the plugin repo when `gh`
write exists.

**Suggestion:** Do not wait for Nous. The bridge already works on loopback.
